# Continue

- **repo:** continuedev/continue
- **version pin:** `v2.0.0-vscode` — gh api repos/continuedev/continue/releases/latest -> v2.0.0-vscode (published 2026-06-19); README calls it the "Final 2.0.0 Release" of VS Code extension, CLI, and JetBrains plugin. Tag v2.1.0-vscode also exists but is flagged prerelease; VS Code Marketplace lists extension 2.1.0; npm @continuedev/cli latest = 1.5.47.
- **docs home:** https://docs.continue.dev (the task's https://continue.dev/docs/intro returns HTTP 404; docs.continue.dev root returns 200 "What is Continue?")

## What it promises

README tagline: "Pioneering open-source coding agent"; the docs home (docs.continue.dev) describes an "Open source AI code assistant for VS Code and JetBrains" whose extensions let developers "create, share, and use custom AI code agents." After the acquisition, continue.dev states: "Continue was acquired by Cursor. Our mission was always to ensure developers are amplified, not automated, and that commitment carries on in the work ahead" — with "our open-source codebase ... freely available as a foundation for others."

## Architecture

Three clients share one TypeScript core: a VS Code extension (webview UI in gui/, engine in core/), a JetBrains plugin (Gradle/Kotlin, extensions/intellij/build.gradle.kts), and the Continue CLI cn (npm @continuedev/cli, bin dist/cn.js; per docs/cli/quickstart "the shell installer bundles its own runtime"). CONTRIBUTING.md documents this split under "Continue Architecture" (VS Code / JetBrains sections). Tools execute client-side: built-in file, search, and terminal tools run in the extension or CLI process under user approval; MCP servers run as spawned stdio subprocesses or remote HTTP/SSE connections (docs.continue.dev/customize/deep-dives/mcp). No daemon or server ships in the final OSS distribution — cn is an interactive TUI or single-shot headless process, and the former cloud Mission Control service is retired.

## Context management

Token-aware summarization plus file-based context. The CLI counts chat-history and tool-definition tokens and auto-compacts near the model's context limit with a 15,000-token buffer cap and 0.8 threshold ratio, rewriting history into one comprehensive summary message (extensions/cli/src/compaction.ts; COMPACTION_PROMPT preserves "key context, decisions made, and current state"). Users trigger the same path manually with /compact ("Summarize chat history into a compact form", docs/cli/tui-mode), and a PreCompact hook event fires first. /fork branches history, /resume restores it. Persistent instructions load from AGENTS.md/CLAUDE.md files and rules — the config reference notes a summarize model role exists but is "not currently used" (docs.continue.dev/reference).

## Ecosystem

Distribution is registry-based: VS Code Marketplace (4,211,679 installs; extension 2.1.0), Open VSX (README badge), JetBrains Marketplace (1,209,416 downloads; vendor "Continue Dev", San Francisco), and npm (@continuedev/cli 1.5.47). The docs ship 10+ third-party MCP cookbook pages (Sentry, Snyk, Supabase, PostHog, Netlify, Atlassian, Notion, dlt, Chrome DevTools) plus agent/check examples in .continue/. The Continue Hub — the assistant/block marketplace whose uses: slugs still appear in config examples — no longer resolves by DNS (hub.continue.dev), and its docs pages return 404, so third-party plugin distribution is effectively frozen at the final release.

## Limitations

The project is finished, not evolving: repo read-only, docs frozen — the task's own https://continue.dev/docs/intro returns 404, as do Mission Control cloud-workflow pages and all /hub/* pages (hub.continue.dev DNS is dead). Hooks, skills, and subagents ship in CLI code but have no documentation (cli/hooks and cli/subagents -> 404). MCP "only works in agent mode" (docs.continue.dev/reference/continue-mcp). README recommends the Continue CLI instead of the JetBrains plugin. No OS-level sandbox/container isolation is documented — only permission gating and read-only plan mode. Cost controls report usage but document no limits. Chat, edit, and autocomplete tool availability depends on the selected model/provider.
