## What it promises

Trae describes TraeCode as 'a development tool deeply integrated with AI capabilities' that 'provides a complete development experience that spans coding, project understanding, debugging and running, and change management', and says you 'can stay in control of every step just as you would in a traditional IDE, or delegate complex tasks to AI agents for planning and execution'. It ships two modes: IDE mode, which 'preserves familiar workflows such as the editor, terminal, debugging, extensions, and source control', and SOLO mode, where 'AI takes the lead'.

## Architecture

TraeCode ships two modes over one product: IDE mode, which 'preserves familiar workflows such as the editor, terminal, debugging, extensions, and source control', and SOLO mode, where 'AI takes the lead' and plans, generates, tests, previews and deploys from a natural-language or voice requirement (https://docs.trae.ai/ide/what-is-trae, https://docs.trae.ai/ide/solo-mode). The primary agent is a built-in 'Agent' for automated project development whose workflow is 'analyze requirements > generate the PRD and technical solution > generate code > preview the result', adding steps such as reading project files, confirming change scope, organizing to-dos and invoking subagents as complexity requires (https://docs.trae.ai/ide/built-in-agent). Custom agents are configured with prompts and toolsets; subagents are Markdown-defined specialists the Agent delegates to, each with an independent context window (https://docs.trae.ai/ide/agent, https://docs.trae.ai/ide/subagents). Command execution can be confined by an opt-in sandbox built on OS primitives, with a per-project sandbox.json defining file and network scope (https://docs.trae.ai/ide/sandbox), or run without confirmation under Auto-Run, which the docs warn 'bypasses all security checks' (https://docs.trae.ai/ide/auto-run-and-security). A separate TraeWork client extends the SOLO idea beyond development into Work, Code and Design modes on web, desktop and mobile (https://docs.trae.ai/solo/trae-solo-quickstart).

## Context management

Context is assembled from an explicit symbol system plus a codebase index. Users add context with # symbols — #Workspace and #Folder draw on the whole project — and the docs warn that 'If code index has not been built or is incomplete, using #Workspace or #Folder to chat with the AI assistant may result in incomplete context recall' (https://docs.trae.ai/ide/number-sign, https://docs.trae.ai/ide/codebase-indexing). Indexing is automatic for projects of 5,000 files or fewer and manual above that, with ignore rules excluding files so that 'your sensitive data remains private' (https://docs.trae.ai/ide/codebase-indexing, https://docs.trae.ai/ide/ignore-files). Persistent context is split across three mechanisms: Rules that regulate AI behavior per project or per matching glob, with documented steps to make AGENTS.md, CLAUDE.md and CLAUDE.local.md work in TraeCode (https://docs.trae.ai/ide/rules); Skills loaded on demand from SKILL.md when a trigger condition matches (https://docs.trae.ai/ide/skills); and Memories, global and project-scoped, stored locally and 'not shared across devices' (https://docs.trae.ai/ide/memories). Long conversations are handled by context compaction (https://docs.trae.ai/ide/context-compaction), and subagents keep their 'intermediate reasoning and execution steps' out of the main chat history (https://docs.trae.ai/ide/subagents).

## Ecosystem

MCP is the extension surface for external tools: 'Through the Model Context Protocol (MCP), you can connect external tools and services to the TraeCode for use', over stdio, SSE and Streamable HTTP, with install links, per-agent usage and log inspection documented (https://docs.trae.ai/ide/model-context-protocol, https://docs.trae.ai/ide/add-mcp-servers, https://docs.trae.ai/ide/use-mcp-servers-in-agents, https://docs.trae.ai/ide/check-mcp-server-logs). Editor extensions come from the Visual Studio Marketplace as VSIX packages (https://docs.trae.ai/ide/manage-extensions). Documented integrations include Figma-to-code, Supabase, Vercel deployment, browser use, Unity, and remote development over SSH and WSL (https://docs.trae.ai/ide/figma-to-code, https://docs.trae.ai/ide/supabase-integration, https://docs.trae.ai/ide/vercel-deployment, https://docs.trae.ai/ide/browser-use, https://docs.trae.ai/ide/develop-apps-with-trae-editor-for-unity, https://docs.trae.ai/ide/ssh-remote, https://docs.trae.ai/ide/wsl). Trae also publishes a community surface of importable custom agents and recommended skills (https://docs.trae.ai/ide/custom-agents-ready-for-one-click-import, https://docs.trae.ai/ide/top-10-recommended-skills-for-development-scenarios), and a separate TraeCode Plugin for VS Code and JetBrains IDEs (https://docs.trae.ai/plugin/install-trae-plugin). Models span multiple vendors plus custom endpoints (https://docs.trae.ai/ide/models).

## Governance

Execution is governed by three layers that the docs treat separately. A directory-permission model makes the root read-only by default — 'all directories not explicitly declared as writable are read-only' — with protected project, temporary, cache and toolchain directory classes (https://docs.trae.ai/ide/permission-and-approval, https://docs.trae.ai/ide/sandbox). An opt-in sandbox confines agent-generated commands and can be tightened per project via sandbox.json, but allowlisted command prefixes 'bypass the sandbox and execute directly outside the sandbox' (https://docs.trae.ai/ide/sandbox). Auto-Run removes confirmation for MCP tools and commands: 'the agent may execute external tools or commands without requiring your confirmation each time', it 'is not recommended … in unverified or untrusted environments', and command Auto-Run 'bypasses all security checks and may result in high-risk operations being executed without warning' (https://docs.trae.ai/ide/auto-run-and-security). Plan review is the other gate: SOLO's Spec and Plan workflows pause for confirmation before execution, and the IDE Agent 'proceeds with development step by step after you confirm the plan' (https://docs.trae.ai/solo/spec-and-plan-as-different-workflows, https://docs.trae.ai/ide/built-in-agent). Hooks can interpose on PreToolUse, PostToolUse, SessionStart, UserPromptSubmit, Stop and Notification events (https://docs.trae.ai/ide/automate-actions-with-hooks, https://docs.trae.ai/ide/hook-configuration-reference). Deleted files go to the OS recycle bin, or ~/.local/share/Trash/ on Linux clients and Remote SSH (https://docs.trae.ai/ide/auto-run-and-security). Spend is metered in dollars against a plan allowance, with On-Demand Usage an explicit opt-in (https://docs.trae.ai/ide/new-plans-and-billing, https://docs.trae.ai/ide/on-demand-usage), and a privacy mode plus device limits bound data handling and account sharing (https://docs.trae.ai/ide/privacy-mode, https://docs.trae.ai/ide/device-limit).

## Limitations

The sandbox is opt-in rather than default, requires per-OS environment setup, needs Remote SSH plus bubblewrap on Linux, and is bypassed entirely for allowlisted command prefixes (https://docs.trae.ai/ide/sandbox). Auto-Run is documented as bypassing 'all security checks', with the docs recommending against enabling it 'unless necessary' and only in trusted environments (https://docs.trae.ai/ide/auto-run-and-security). Memory 'is stored locally and cannot be shared across devices', and some categories are not saved unless explicitly requested (https://docs.trae.ai/ide/memories). Context recall depends on the codebase index being built: projects over 5,000 files need a manual index trigger, and an incomplete index yields 'incomplete context recall' (https://docs.trae.ai/ide/codebase-indexing). Hook parameters are not compatible with Claude Code's despite shared event names: 'The input and output parameters for hook events with the same name may differ between TraeCode and Claude Code' (https://docs.trae.ai/ide/automate-actions-with-hooks). Platform-specific extensions such as C/C++ cannot be installed from the in-app marketplace and need a manual VSIX download (https://docs.trae.ai/ide/manage-extensions). No fetched page documents resuming a previous session, only forking a chat from an earlier response (https://docs.trae.ai/ide/chat). The documentation itself is only readable through the site's server-rendered payload — llms.txt, sitemap.xml and .md paths all return the SPA shell — and the product's public version signal is a changelog page whose newest entry covers a version range rather than a single release (https://docs.trae.ai/ide/changelog).

## Notable

The documentation site is a client-side SPA with no llms.txt, sitemap.xml, .md variant or public content API — every one of those returns the same 287 KB app shell, so the pages have to be read out of the server-rendered payload (scripts/fetch-trae-docs.py in this repository does that). Two documented gaps cut against the polished surface: the sandbox is opt-in and its allowlist 'bypass the sandbox and execute directly outside the sandbox', and Auto-Run is described as a mode that 'bypasses all security checks and may result in high-risk operations being executed without warning'. Trae also ships a separate plugin product for VS Code and JetBrains, so it is both an IDE and an extension for other IDEs.
